# 从编程语言到自然语言接口

人用语言驱动机器。经典计算机上，这门语言是编程语言，实现按可检查的规则执行。大模型上，这门语言是自然语言，模型按习得的分布把句子接下去。差距集中在中间层。

编程语言用了几十年，在人的文本和世界效应之间放进语法、类型、核心语言、效应处理，以及引用监视器（reference monitor，拦截每一次敏感访问的组件）。自然语言接口要可靠，需要同一套中间层。自然语言继续担任对人的表面语法。模型担任阐述者和局部搜索器：把欠规定的意图变成内部语言上的候选。类型检查、权限、重放，以及写得出性质的正确性判定，留在运行时，留在确定性的程序里。

本文先固定类比的角色，再按语言实现的层次检查哪些概念能够迁移，最后给出失效条件和借鉴顺序。

## 1. 类比落在角色上

「计算机以编程语言为输入和输出，大模型以自然语言为输入和输出」这个观察成立，但对应关系要落在系统中的角色上，而不是落在字符串相似上。

| 角色 | 经典计算 | 大模型系统 |
| --- | --- | --- |
| 写程序的人 | 程序员 | 设计系统提示、工具、工作流的人；终端用户有时也在改写「程序」 |
| 外部语言 | 编程语言的表面语法 | 自然语言，加上模式、工具描述、示例 |
| 阐述 | 消解重载、补上省略的类型、拒绝无法翻译的句子 | 模型把意图补成结构；补不上时应反问，而不是猜 |
| 内部语言 | 核心演算、中间表示 | 任务、计划、工具请求等可检查的数据 |
| 解释 | 求值器或代码生成 | 代理循环、解码器、工具处理程序 |
| 数据 | 程序的参数 | 用户话语、文档、网页、工具返回 |
| 效应 | 系统调用 | 工具调用 |
| 运行时 | 运行时库与操作系统 | 预算、沙箱、策略监视器、追踪 |

经典机器的输出如果仍要被机器消费，会落回形式语言：返回值、字节、结构化数据。大模型的输出若仍是自然语言，接收方就再当一次解释器。解释器套解释器，歧义相乘。内部语言的一步应当停在类型化的值或效应请求上。对人说话时，再渲染成自然语言。

四条不对称决定了后面每一项类比能走多远。

1. 形式语言可以在执行前拒绝不合式的程序。自然语言几乎总能被模型接下去，失败表现为答非所问，而不是语法错误。
2. 形式语言的语义写在规范里，实现可以被规范裁决。模型的语义写在权重里。换一个模型版本，同一段话的含义分布就变了。这相当于语言规范等于某一版解释器，而且解释器会在源文本不变时自行更换。
3. 形式语言里，代码和数据有语法地位之别。自然语言里，指令和被处理的文本是同一种句子。用户既是调用者，又是程序文本的一部分。
4. 形式语言追求组合：部分正确，加上组合规则，得到整体正确。自然语言的组合是近似的，语用会改写字面意思。

因此编程语言在这里的身份是接口工程的先例。每一项纪律都要问：它在随机、开放、代码与数据同形的接口上，还能否被机器检查。能检查的，放进运行时。只能写进系统提示里劝模型遵守的，不算迁移成功。

## 2. 这一领域处在语言史的哪一段

编程语言的成熟是一层层约束加上去的。自然语言接口正在重演前几层，后几层刚开始。

| 编程语言的阶段 | 自然语言接口中的对应 | 现状 |
| --- | --- | --- |
| 机器码 | 手写提示，靠措辞试错，行为绑在某个模型的癖好上 | 仍是许多系统的起点 |
| 汇编与宏 | 提示模板、少样本、字符串拼接 | 能复用，没有语义边界 |
| 把表面语言嵌进真正的宿主语言 | LMQL 一类语言模型编程；DSPy 的签名与模块 | 控制流回到程序，模型负责局部生成 |
| 结构化程序设计 | 显式状态机、循环、预算，取代自由跳跃的思维链 | 正在成为共识 |
| 过程与模块 | 工具、技能、子代理 | 有了名字，上下文仍常常是一块全局内存 |
| 类型与契约 | 模式、约束解码、工具参数校验 | 类型出现在边界上 |
| 编译 | 把声明式调用编译成指令、示例甚至权重 | 架构可借鉴；语义保持不再自动成立 |
| 托管运行时 | 追踪、重放、沙箱、记忆、权限监视器 | 语言的价值开始更多来自运行时 |
| 大规模编程 | 技能仓库、模型与提示的锁文件、语料版本 | 系统已经是「大规模」的，手段仍是「小规模」的 |
| 语言安全与验证 | 信息流、能力隔离、轨迹性质 | 研究已经做出运行时，尚未成为默认 |

DeRemer 与 Kron 在 1975 年区分了小规模编程与大规模编程：前者关心算法和语句，后者关心模块、依赖和版本。代理系统已经处在大规模——几十个工具、多层委托、随时变化的检索语料——同时仍用小规模的手法：一份不断追加的系统提示，外加一个循环。

这个阶段差说明哪些教训值得提前拿走。全局可变上下文、把不可信字符串送进控制流、环境权限、只靠黄金样例回归，都是编程实践里后来付出高价才退出主流的做法。

## 3. 概念对照

下表是库存。迁移成功的标志见第 1 节：纪律要能在运行时被检查。

| 编程语言中的概念 | 它管什么 | 自然语言接口中的对应 | 借鉴方式 |
| --- | --- | --- | --- |
| 词法与语法 | 拒绝不合式的程序 | 约束解码、JSON Schema、工具参数语法 | 用在边界上 |
| 抽象语法树 | 让文本变成可变换的结构 | 计划、工具调用、任务表示是数据 | 直接作为内部语言 |
| 外部语言 / 内部语言 | 方便的表面语法与小核心分离 | 自然语言为外部语言，任务与效应为内部语言 | 这是整个类比的骨架 |
| 阐述（elaboration） | 翻译时消歧、补类型、拒绝无法翻译的句子 | 模型补槽；无法唯一确定时反问 | 直接可用；猜一个默认值等于危险的隐式强制 |
| 静态类型 | 执行前排除一类错误 | 工具签名、输出模式 | 用在穿过信任边界和效应边界的值上 |
| 渐进类型 | 允许部分区域没有类型 | 自由推理与结构化槽混排 | 野心的上限就在这里 |
| 责任（blame） | 契约失败时指出哪一侧违约 | 模式失败要指向槽位、工具描述或未类型化的推理 | 与渐进类型一起搬 |
| 精化类型 | 类型里写下值的性质 | 日期范围、金额上限、枚举闭集 | 由确定性检查器执行 |
| 进展与保持 | 良构状态不会无定义地卡住；一步之后不变式仍在 | 代理一步要么完成，要么发出合法效应，要么进入已定义的错误 | 用来验收运行时 |
| 效应系统 | 标明副作用的种类 | 读、写、花钱、外发、不可逆操作 | 直接可用 |
| 线性类型与所有权 | 资源的使用次数和别名 | 批准、凭证、支付意图；关键事实的唯一权威位置 | 作为运行时纪律 |
| 会话类型 | 通信必须符合协议 | 人、代理、工具之间哪些迁移合法 | 用状态机执行 |
| 操作语义 | 规定一步如何计算 | 代理循环写成小步规则 | 小步语义适合写；大步语义盖住中间效应 |
| 求值策略 | 传值、传名、惰性 | 先算完子问题，还是把问题传下去，还是按需检索 | 直接可用，并要显式选择 |
| 合流性 | 归约顺序不影响结果 | 工具顺序常常影响结果 | 用来否定「让模型随便重排」 |
| 观察等价 | 外部看不出差别才叫等价 | 比较效应轨迹、结局和资源，不比较内部措辞 | 等价的定义本身要改写 |
| 指称语义 | 程序对应独立于实现的数学对象 | 提示词的意义随模型移动 | 停在实现上的语义，改用轨迹集合 |
| 未定义行为 | 规范没覆盖的地方，实现可以做任何事 | 「模型大概会做对」覆盖了绝大部分句子 | 每个效应都要有定义好的处理或拒绝 |
| 编译与优化 | 降到低级语言并保持语义 | 降到 SQL、代码、计划；自动搜索提示 | 架构可用；每次提示搜索都是行为变更 |
| 中间表示 | 分析与优化的落点 | 计划图、工具指令、类型化轨迹 | 优先落地 |
| 链接与 ABI | 程序与库在约定上结合 | 检索是动态链接；工具协议是调用约定；技能是库 | 调用约定不自动带来安全 |
| 宏卫生 | 展开时不捕获现场的自由名字 | 检索文本和不可信内容捕获代理的目标 | 类比很紧；卫生靠通道，不靠分隔符 |
| 引用（quotation） | 把代码降为数据 | 自然语言没有解释器必须遵守的引号 | 用来说明文本隔离不够 |
| 信息隐藏 | 模块按可变的秘密切开，只暴露接口 | 技能隐藏供应商、提示和重试；子代理只收投影 | 需要单独的上下文才成立 |
| 分离逻辑的局部推理 | 一段计算只依赖堆的一个区域 | 子任务只依赖状态的一个区域，其余对它不可见 | 借局部性，不借证明规则的细节 |
| 能力安全 | 没有环境权限，只有被授予的能力 | 按任务铸造工具能力，带范围和时限 | 直接可用 |
| 代数效应与处理程序 | 程序请求效应，外部决定如何解释 | 模型发出工具请求；执行、拒绝、模拟、重放是不同解释 | 这就是代理运行时应有的形状 |
| 单子 | 把效应从值里分离出来再组合 | 效应的早期包装；解释策略写在单子内部 | 处理程序更贴近现状：解释可以整份替换 |
| 结构化控制 | 顺序、分支、循环、过程 | 工作流、预算、已定义的失败结局 | 直接可用 |
| 续延 | 把剩余计算变成可以放下的对象 | 等待人工批准；持久执行 | 记录续延的外部选择即可重放 |
| 契约 | 前置、后置、不变式 | 工具前置条件、输出检查、花费与授权不变式 | 直接可用 |
| 生成与检查分离 | 搜索证明难，检查证明容易 | 模型提议候选，确定性程序接受或拒绝 | 方法论上优先 |
| 属性测试与蜕变测试 | 用性质代替单个黄金例子 | 改写问题后在指定等价下不变；失败必须进入失败状态 | 直接可用 |
| 变异测试 | 改掉程序里的一处，套件应当变红 | 删一条安全规则或改一个工具描述 | 用来检验评测有没有覆盖那条规则 |
| 模糊测试 | 随机输入寻找崩溃 | 随机说法、编码、间接指令 | 与功能评测同一套基础设施 |
| 抽象解释 | 不运行，过近似程序会碰到什么 | 这段计划可能触网吗、可能外泄吗 | 用在工具图上 |
| 信息流控制 | 机密性与完整性沿允许的通道流动 | 不可信内容不能流入控制状态和高完整性参数 | 直接可用，监视器在模型上下文之外 |
| 困惑的代理 | 程序的权限被无权的数据驱使 | 代理拿用户权限阅读攻击者控制的内容 | 问题的正确名字 |
| 渐进安全类型 | 未标注部分可以逐步纳入 | 老工具没有标签时，用有界的强制并记下责任 | 适合增量部署 |
| 并发、参与者、π 演算 | 私有状态加通信；通信拓扑会变 | 多代理的委托本身在改变拓扑 | 用消息，不用共享散文 |
| 控制流劫持 | 不可信数据改写后续控制 | 子代理把攻击者的「修复建议」交回编排者 | 委托边上单独保持完整性 |
| 垃圾回收 | 回收不可达对象 | 摘要与压缩 | 先定义根集；否则压缩是有损变换 |
| 区域与生命周期 | 资源活在一个词法范围内 | 全局规则和记忆的作用域 | 直接可用 |
| 锁文件与语义版本 | 依赖可复现，兼容性可声明 | 锁定模型、解码参数、提示、模式、语料 | 对模型可见的文本默认按破坏性变更对待 |
| 录制重放 | 再现一次执行 | 记录模型标识、检索命中、工具返回、人工批准 | 直接可用 |
| 诊断 | 指出位置和修法 | 校验失败返回字段、期望类型、缺失项 | 直接可用 |
| 嵌入式领域语言 | 窄语义寄生在宿主语言上 | 内部语言用真正的编程语言承载 | 不要用自然语言重做模块系统 |
| 分阶段计算 | 已知部分先特化 | 能变成查询、代码、事务的子任务立刻降下去 | 直接可用 |
| 静态分析式的 lint | 在运行前指出可疑形状 | 矛盾规则、过宽工具、不可测试的口号 | 作用在内部表示上 |
| 评审、差分、持续集成 | 变更可审，回归可门禁 | 计划与策略的差分；模型或提示变化必须跑评测 | 散文差分几乎不可审 |
| 金丝雀与特性开关 | 实现更换时控制爆炸半径 | 模型版本更换比普通应用发布更接近编译器升级 | 直接可用 |

## 4. 骨架：外部语言、阐述、内部语言

编程语言后来的技术，都建立在一个决定上：不直接执行表面文本。表面语法先阐述成一个小的核心语言。重载在这一步消解，省略的信息在这一步补上，无法翻译的句子在这一步被拒绝。核心语言才有操作语义。优化、证明和调试都作用在核心语言上。

自然语言接口的默认做法仍是直接执行表面语言。模型在同一段散文里规划、调用、观察、再规划。这相当于把源文本当作机器码。

更准确的角色分工如下。

- 外部语言是自然语言。它允许欠规定，允许省略，允许人在还不知道全部约束时就开口。
- 阐述由模型完成局部搜索，由模式和对话完成约束。能够唯一进入内部语言的，就进入。存在多个都合法的解释时，向人要一次标注，也就是反问一个槽位。静默选一个解释，相当于语言里的隐式强制。C 的隐式转换，以及 PHP、JavaScript 的类型强制，留下的是整类难以定位的错误。
- 内部语言是任务、约束、预算、权限、计划和效应请求。它小，它的一步有定义。
- 宿主语言是一门真正的编程语言。内部表示、模块、测试和版本控制寄生在它上面。这是嵌入式领域语言的路线。LMQL 把约束放进查询，DSPy 把签名和模块写成可编译的程序，走的都是这条路。差别在于内部语言有多小、效应有没有被处理程序接管、检查器是不是确定性的。

由此得到的栈：

```text
人的意图（外部语言）
  → 阐述：补槽、消歧；无法唯一确定则反问
  → 任务：目标、约束、预算、权限
  → 计划：控制与数据流，节点是数据
  → 效应请求：带能力的工具调用
  → 处理程序：策略、沙箱、重试、模拟、重放
  → 观察写回内部状态
  → 检查器：契约与不变式
  → 只在对人说话时渲染成自然语言
```

把模型叫做随机编译器，会漏掉责任边界。编译器对语义保持负责。模型对候选负责。语义保持由内部语言的检查器、以及后端那门精确语言负责。DSPy 一类编译器搜索的是指令和示例，使某个度量变好。这个搜索可以保留。它的每一次输出都按行为变更对待，并用评测当门禁。「优化器理应保持语义」不能作为跳过评测的理由。

小步规则可以写成进展与保持，用来验收运行时。

- 进展：良构状态要么已经完成，要么能发出一个合法的效应请求，要么停在已定义的错误上。已定义的错误包括等待人工、预算耗尽、策略拒绝、参数不合模式。模型吐出无法解析的工具调用时，运行时要把它变成修复步或已定义错误。停在「上下文里多了一段乱码，然后继续产生效应」是进展失败。
- 保持：每一步之后，标签、预算、能力集合和任务不变式仍然成立。

大步语义把一次任务收成一个输入输出对，中间效应被盖住。代理的问题恰恰出在中间效应上，所以规格要写成小步。

## 5. 类型落在边界上

对整段自然语言做静态类型，会取消人们使用它的原因：它故意说得不完全。渐进类型才是对等的野心。自由推理可以没有类型。凡是要穿过信任边界、产生效应、被下游程序消费的值，都要有类型。

由浅到深：

- 简单类型是工具的参数和结果模式，也就是函数签名。
- 精化是模式之外的谓词：日期晚于某个下界，金额不超过预算，接收方属于闭集。模型提议候选，精化检查器拒绝不合格的候选。检查器是普通程序或求解器。
- 效应把「草稿」和「真正发出」分成不同的类型。读、写、外部可见、不可逆、花费，是不同效应。没有相应效应的代码，在类型上就无法触碰那类操作。
- 线性纪律用于消耗品。批准、凭证、支付意图用过即失效，不能复制后使用两次。关键事实则要有唯一的权威位置。同一事实在上下文里出现两遍且互相冲突，是自然语言里的别名问题。所有权系统里值得搬的是这个纪律，不是把借用检查器做进句子。
- 会话类型把多轮协议写成状态机。哪些状态可以取消，哪些状态必须确认，运行时拒绝非法迁移。模型负责把对话推进到合法状态。
- 双向检查解释一种已经有效的实践：输出模式已知时从目标回推，中间推理没有目标类型时保持开放。规定输出的类型，放任推理的措辞。规定推理过程的每一句，通常更脆。

渐进类型里的责任分配同样适用。契约失败时，指出是槽位缺失、工具描述与实现不符，还是未类型化推理产出了坏值。只说「代理错了」，相当于类型错误不给位置。

生成与检查的分工是这一层最重要的方法论。搜索难，检查容易。能写成程序的性质，用程序检查。另一个模型担任的法官，只处理还没有形式性质的判断，并且法官的权限本身是一种效应：它能拒绝候选，不能凭自己的散文去调用工具。

## 6. 求值策略是设计选择

代理循环的状态里有目标、计划、上下文、预算和待处理效应。一步归约是：选择一个效应，交给处理程序，把观察写回，或判定完成与失败。各种框架的差别，很多是归约策略的差别。

- 传值：子问题先算出具体结果，再交给下一步。结果稳定，成本高，也可能过时。
- 传名：把问题本身传下去，由使用方决定何时展开。灵活，也更容易捕获错误的上下文。
- 惰性：没有消费者就不检索。节省上下文，也可能漏掉只有提前看到材料才能发现的约束。

这些策略没有普遍的优劣。它们必须是计划上的显式标注。纯 λ 演算里顺序无关的直觉在这里不成立。先订票还是先查签证，结果不同，系统并非合流。计划语言要写出数据依赖，重排只允许发生在没有依赖、并且效应允许重排的节点之间。

若坚持给提示词一个指称，那个对象也只能是某个模型、某组解码参数下的轨迹分布。模型一换，指称就换。可以稳定比较的是观察等价：对外请求了哪些工具、以正常还是异常结局结束、消耗了多少预算。有界提示流水线的效应语义里有一个相应的细节：异常会丢掉后面的续延；若把被丢掉的调用也算进轨迹，轨迹就不再在方程下保持。观察必须记录真正发生的效应，并且带上结局。

未定义行为是同一件事的规范视角。C 的教训是，规范没覆盖的地方会毒化周围的推理。对代理来说，「模型大概会做对」就是未定义行为，而且它覆盖了绝大部分自然语言。收紧的办法是让每个效应要么有定义好的处理，要么被拒绝。没有第三种「先执行，再看模型怎么圆」。

## 7. 绑定、卫生，以及没有引号

编程语言里的作用域、闭包和宏卫生，回答的是同一个问题：这段话里的自由名字绑定到哪里。

自然语言默认动态绑定。「那个文件」「上面的结果」「按刚才的格式」都依赖当下上下文。上下文一长，名字就捕获到错误的对象。关键参数应当放进槽位。代词可以留在对人的表面句子里，不应当承载效应参数。

宏卫生描述的是展开时的捕获。宏带来的名字不应意外绑到使用现场的名字上，使用现场的名字也不应绑进宏的内部。把检索结果或网页正文拼进上下文，就是一次展开。不可信文本捕获代理本来绑定在用户目标上的控制权，就是不卫生的展开。提示注入是这个现象的安全形态。

分隔符和「请忽略以上指令」相当于用注释保证卫生。展开器并不把注释当语法。Lisp 的引用能把代码降为数据，是因为解释器尊重引号。自然语言里的任何标记都只是惯例，模型可以把它读成需要服从的句子。

因此隔离建立在通道上。不同信任域用不同的数据结构进入运行时。控制状态不由一段可拼接的字符串承载。参数化查询是同一教训的旧形式：数据走进槽位，不拼进会被解释的文本。工具参数走模式，不走「把用户的话接在命令后面」。

检索是动态链接，也是宏展开。链进来的文档会改变行为，又常常不在锁文件里。不可信检索与不可信用户文本使用同一套卫生规则。

## 8. 效应处理程序就是运行时

代数效应的形状与工具调用一致。程序里只出现请求：需要检索，需要调用某个工具，需要模型再生成一段。请求不是执行。处理程序在外面决定真的调用、使用缓存、拒绝、记日志、重放上次的返回值，或在测试里返回假数据。更换处理程序时，任务程序保持不动。

单子早先把效应从普通值里分离出来，使计算可以组合。处理程序把「如何解释这些效应」也变成可以替换的模块。代理运行时需要的是后者。

由此而来的义务：

- 模型权重里不产生世界效应。唯一能产生世界效应的是处理程序。
- 重试安全的工具要标明，并带幂等键。不幂等又没有幂等键的效应，不能自动重试。
- 多步效应要有补偿。补偿是处理程序的逻辑，不寄托于模型在失败后临时想出回滚步骤。
- 测试、录制和真实执行是同一组请求的三个解释。没有这层接口，测试就只能打真服务。
- 预算是资源效应。次数、token、延迟和钱记在处理程序上。耗尽是一种异常结局，进入已定义的失败状态。

能力安全与效应标注是同一边界的两侧。模型可以提到某个工具的名字，不等于当前任务持有那个能力。能力由运行时按任务铸造，带范围和时限。网页正文和「发送」的能力不应出现在同一次求值里。

## 9. 安全是语言安全

内存安全的历史最有预言性。早期防御是谨慎和危险函数扫描。后来违约率下降，是因为一类错误在语言里没有语义，或者没有能力就调用不到。

提示注入是完整性失效：低完整性数据改写了高完整性的控制。数据外泄是机密性失效：高机密性数据流向了低机密性的出口。信息流控制把两者写成标签。不可信内容被读入后，标签污染后续状态。被污染的状态不能流入高完整性的效应参数，也不能流入低机密性的出口，除非经过显式的背书或降密。

背书发生在模型上下文之外的监视器里。若「是否允许」仍是模型在同一段可被对手改写的上下文里做的判断，策略和攻击面就重合了。2025 到 2026 年的一批系统已经按这个方向把监视器做进运行时。Fides 用规划器跟踪机密性与完整性标签，把工具结果放进变量，需要查看时用隔离的查询和约束解码取出类型化结果。FLOWSEAL 把机密性策略放在工具拦截器上，依据来源而不是依据模型的自我审查。APPA 把检查放在工具分发和协议网关（包括 MCP）上，用有界的子分支查看不可信数据，再经形状受限的通道回到主轨迹，并讨论了渐进安全类型，以便尚未标注的旧工具能够逐步纳入。

困惑的代理（Hardy, 1988）是精确的名字。代理的权限大于喂给它的那段内容所应拥有的权限，内容驱使代理行使了多余的权限。能力安全的回答是取消环境权限。读者与执行者分离：读者接触不可信文本，执行者只接收有界的、类型化的字段。

多代理把这个问题再放大一层。编排者往往只看见子代理的报告，看不见子代理读过的不可信内容。控制流劫持的手法，是把攻击写成「看起来像失败诊断」的委托返回值，编排者信任自己人，于是按攻击者的建议重新规划。完整性要沿着委托边传播。消息来自内部代理，并不构成洗白。π 演算当初要描述的就是通信拓扑会变化的进程。多代理的委托在运行中改变拓扑，会话类型和边上的标签比「大家共享一份白板」更接近这门演算的纪律。

表面防御——更长的系统提示、口头上的全面禁止、对已知句式的过滤——挡的是某一种说法。换一种框架，同一效应仍会出去。协议设计里 Postel 定律留下的教训与此平行：对接收端过于宽容，歧义会变成永久兼容负担。代理的效应边界应当严格。不合模式的参数直接失败，不由模型理解一个大概意思再执行。

工具协议统一了调用约定。调用约定本身不提供信息流和最小权限。那两件事仍由语言和监视器提供。

## 10. 模块、并发与资源

Parnas 的切分标准是按可能变化的秘密来切模块。一个技能应当隐藏用哪家检索、提示长什么样、失败如何重试。对外暴露的是任务级接口。按「第一步、第二步」切开的系统提示，秘密留在步骤之间，换供应商就要改所有步骤。

信息隐藏有一个物理前提：实现细节若留在同一上下文窗口里，模型仍然读得到，也仍然会被它影响。真正的模块是分开的上下文。模块之间只传类型化的值。子代理收到的是任务所需的投影。Reynolds 的抽象性质给出同一纪律的强化形式：一段计算若只能通过类型看见数据，就不能依赖数据的表示。这同时是信息流里「规划器没有读取原文」的一种说法。分离逻辑里的局部推理提供同一直觉：子任务只依赖状态的一个区域，其余区域不进入它的上下文。

上下文窗口是这一领域的存储瓶颈。它线性、全局可见，指令和数据放在一起，靠位置和注意力寻址。把一切都追加进同一窗口，是用最原始的存储模型编写系统。

工具数量还有语言设计上的后果。庞大的全局规则集带来特性交互：两条各自合理的规则放在一起，行为无法从各自的说明推出。小核心加可选的库，比把所有策略写进每个任务都加载的系统提示，更接近成熟语言的形态。每增加一条全局规则，都是在给语言加特性，需要和其他特性一起测试。系统提示是语言设计，不是配置杂项。

多代理若共享一块谁都能写的自然语言状态，就重演了没有同步的共享内存。竞态的表现形式是两段矛盾的话同时活着，模型按注意力挑一句。参与者模型更适合作为默认：私有状态，类型化消息，编排者看见结果。必须共享的事实要有所有者和合并规则。并行分支的状态合并应当写明是后者覆盖、按键合并，还是冲突即失败。

资源纪律另列：

- token、延迟和金钱出现在效应和预算里。耗尽是控制流的一部分。
- 批准和支付意图遵循线性纪律。
- 摘要压缩类似垃圾回收，但常常没有可达性定义。垃圾回收可以收集的是从根不可达的对象。摘要器可能丢掉一个没有再次被提及、却仍被后续约束依赖的事实。在定义根集之前，压缩只作用在可重建或明确可丢弃的区域。关键事实留在类型化状态里，不参加散文级回收。
- 系统提示只增不减、旧指令无法撤销，是泄漏。规则需要作用域和生命周期。

注意力也不是词法活性。一条看起来用不到的规则仍然占据注意力，仍然可能改变行为，不能按死代码删除。位置、重复和邻近都会改变绑定。语义缓存是用近似相等做记忆化，只有对声明的等价标准封闭、并且没有效应的计算才能进入。

## 11. 测试、诊断与版本

霍尔逻辑能迁过来的内核是：为一小段计算写下前置和后置，用不变式穿过循环。代理循环的不变式常常是安全性质。花费不超过额度。未经确认不执行不可逆工具。不可信标签不进入外发参数。这些性质放在确定性监视器里。

抽象解释适合用在计划的工具图上，忽略措辞，过近似这段计划可能达到哪些效应。它回答「能不能」，不回答「这一次的措辞会不会碰巧拒绝」。

测试要按并发程序的方式接受非确定性。

- 黄金轨迹容易过拟合，作用更接近脆弱的快照。
- 性质和蜕变关系更适合充当判定标准。改写问题后，答案在事先声明的等价下不变。无关文档的顺序变化，不改变工具参数。工具报错后，系统进入失败状态，不继续执行不可逆动作。
- 变异用来检验套件。删掉一条安全规则，或把工具描述改宽，相关测试应当变红。仍然全绿，说明套件没有覆盖那条规则。
- 模糊测试覆盖随机说法、编码和间接指令。对抗样本是模糊测试的输入，不是另一套神秘流程。
- 门禁写成失败率的上界，并重复运行。单次布尔值会被抽样噪声左右。

诊断是语言用户体验里杠杆很高的一部分。参数校验失败时，返回字段、期望类型和缺失项，让同一次循环能够修复。把原始异常倒进上下文，等于把编译器内部转储交给模型，并希望它由此变成编译器。

录制重放记录的是决定轨迹的外部选择：模型标识与解码参数、检索命中、工具返回、人工批准。内部措辞可以不作为重放的依据。没有这些外部选择，生产故障不能在本地再现。等待批准的代理是一个被放下的续延。持久执行要保存的是这个续延的外部选择，而不是保存整段散文并指望下次生成出同样的决心。

版本管理面对的是一种很硬的依赖。对模型可见的文本既是文档也是程序，改一个词就可能是破坏性变更。没有稳定 ABI 那种幸运的中间层。锁文件里至少有模型版本、解码参数、提示与技能的哈希、工具模式的哈希、语料或索引的版本。语义版本在这里取保守规则：对模型可见的文本，默认按破坏性变更走评测。检索语料的更新是依赖更新，进入同一套门禁。

依赖冲突的症状是多条技能和多份文档互相矛盾，模型按注意力选择胜者。处理办法与包管理相同：显式依赖，单一权威，冲突即失败，而不是把两份副本都放进上下文里希望和解。

实践中的其余对应关系：

- 评审作用在计划、策略和模式的差分上。散文差分难以判断行为。
- lint 查找矛盾规则、过宽的工具权限、缺少后置条件的效应、无法写成性质的口号。
- 模型版本更换使用金丝雀和特性开关。它更接近更换编译器，而不是发布一次界面改动。供应商侧的静默升级，相当于依赖在持续集成之外被改写。生产环境钉住版本。
- 内部表示一旦存在，就可能有语言服务：跳到技能定义，查找一条策略的引用，重命名槽位，在签名变化时列出受影响的调用。
- 设计模式需要节制。ReAct 这类循环弥补的是内部语言尚未形成时的空缺。计划成为数据之后，循环应当收进运行时，不必在每个提示里再写一遍。

## 12. 能离开自然语言的部分立刻离开

分阶段计算的实用形式是：自然语言做前端，精确语言做后端。用户说出目标，系统把已经确定的承诺编译成查询、程序、约束或事务，然后执行那种语言。那种语言自带类型检查、优化和沙箱。模型不再担任整个计算的解释器。

这是部分求值。模式、权限和可用工具是已知的，这次的具体意图是未知的。能在进入循环之前固定的策略，不要在每一次生成里重新解释。让模型写出一段程序并用程序的结果作答，是这个原则的特例。前提是那段程序跑在真正的语言实现里，效应被沙箱限制。模型发出的代码，其语言运行时就是安全边界。

计划一旦是数据结构，就能做静态检查、差分、缓存和重放。代码即数据在这一层成立。对人的解释可以从数据结构渲染出来，渲染结果不回写为权威状态。

## 13. 语言设计上的戒律

从语言设计史里可以直接抽出这些戒律。

- 核心保持小。全局规则越少，特性交互越少。
- 库与核心分离。领域策略放在可选择的技能里。
- 后端可替换。任务程序不写死某个模型的格式癖好。模型是后端。
- 规范先于实现。技能的说明独立于模型：输入、输出、效应、失败、要保持的性质。评测对照的是这段说明。
- 错误可定位。运行时对调用方负有诊断义务。
- 扩展保守。新工具和新的全局规则要说明可能冲突的旧规则，并带测试。
- 内部语言标准化，表面方言不必标准化。Landin 在《下一个 700 种编程语言》里抱怨表面语法层出不穷，核心却没有变清楚。代理框架容易重复这件事。值得对齐的是任务表示、效应请求和轨迹，而不是再发明一种提示方言。

## 14. 语言学补上的部分

有几件编程语言不会自动提供、而自然语言研究已经命名的事。它们说明哪些纪律必须放在运行时，而不能放在字面意思上。

言语行为理论区分说话和做事。请求、承诺、宣布，效果不同。工具调用是一种行事。「模型说出它将要删除」和「删除已经发生」必须是两种状态。这个区分就是效应请求与效应处理。

语用学会补全省略，也会把暗示当成要求，把礼貌的否定理解成可以变通。格莱斯式的会话含义说明：字面规范挡不住听话人补出来的意思。安全性质不能依赖模型对语气的理解。

组合性原则希望部分的意义合成整体的意义。真实话语经常做不到，上下文和言语行为会改写部分。因此「模块各自正确则整体正确」在散文层不成立。它只在内部语言上还有机会成立，因为内部语言的组合规则是我们自己规定的。

回指是绑定问题的语言学形态。代词的解析依赖话语结构。这支持第 7 节的纪律：效应参数进槽位。

形式语言的层级有一部分本来来自对自然语言句法的研究，随后在编程语言里成为工程工具，在自然语言里则被证明不够用。两边重新相遇时的分工是：形式骨架做内部语言，自然语言做外部语言。

## 15. 类比失效的地方

这些失效决定借鉴的上限。

1. 没有独立于实现的语义。两个 C 编译器可以拿标准来裁判。两段提示在不同模型上没有外部裁判。任何「重构保持行为」的说法，都要附带模型版本、解码参数和度量。
2. 等价对局部措辞敏感。改一个词，分布可能换一种做法。差分和小型修改仍然有用。把提示词当作可以做等式推理的项，会推出不存在的保证。
3. 代码与数据同形，是这门接口的需求。用户要用同一种语言下指令和提供内容。在表面语法上恢复彻底的代码/数据分离，等于放弃自然语言接口。分离重建在运行时和通道上。
4. 欠规定是功能。人开口时常常还不知道全部约束。效应边界上变严，中间推理保持开放，是适应这种功能的类型纪律。
5. 上下文不是随机访问内存，注意力也不是词法活性。死代码消除、公共子表达式消除和普通记忆化不能原样搬进提示词。
6. 训练与编程是两层。训练决定这台机器如何解释句子。提示、内部语言和运行时是在这台机器上编程。类型、效应和模块作用在外层。它们不从权重里抽出一份可证明的语义。
7. 许多语言任务的正确性是分级的，而且依赖场合。形式工具包扎的是写得出性质的部分：效应、预算、模式、策略、协议。其余部分保持为评测、审查和人工接受。

## 16. 借鉴顺序

按类比有多紧、做错的代价有多大来排。

架构上采用这些形状。

1. 效应与处理程序分离。模型提议，运行时执行、拒绝、模拟或重放。
2. 外部语言与内部语言分离。任务、计划和工具调用是数据。自然语言出现在对人渲染和阐述的两端。
3. 内部语言寄生在真正的宿主语言里。模块、测试和版本控制不重做在散文上。
4. 能降到精确语言的子任务就降下去：查询、代码、约束、事务。
5. 能力按任务铸造，带范围和时限。同一次求值里不同时出现不可信文本和高权限效应。
6. 信息流标签由运行时跟踪。标签阻塞的是效应参数和出口。
7. 边界上使用类型、精化和契约。检查器是确定性程序。无法唯一阐述时反问。
8. 控制流结构化。一步满足进展与保持。不可逆效应不放进无法定位的散文跳转里。
9. 用锁文件和轨迹记录钉住模型、提示、模式、语料和工具返回。

用来保证架构确实被遵守。

10. 性质测试、变异测试、统计门禁，以及针对注入和外泄的模糊测试。
11. 校验失败和策略拒绝返回可修复的结构化原因，并带责任位置。
12. 子代理默认不继承父上下文，只接收投影。
13. 批准一次有效。关键状态不进散文级摘要。全局规则有作用域。
14. 多代理使用消息。委托边上的完整性单独保持。共享事实有所有者、有合并规则。

只借问题的形状，不借原来的定理。

- 指称语义改为可接受轨迹的集合，轨迹包含结局和资源。
- 提示搜索可以保留，每次结果都是行为变更，用评测把门。
- 类型保持渐进，严格性集中在效应边界。
- 压缩先定义根集，再谈摘要。
- 重构条目都标注它依赖的等价。没有标注的视为行为变更。

这些做法会把旧问题再标准化一次。

- 用文本分隔符模拟作用域和引用。
- 用更长的系统提示模拟类型检查器和引用监视器。
- 用黄金样例的一次通过代替语义保持。
- 默认工具调用可以重排。
- 默认上下文里没被提到的指令是死代码。
- 用自然语言重新实现一套模块、类型和作用域。

## 17. 压缩

编程语言变得可靠的标志，是人不再直接对着机器不规则的部分说话。中间有阐述、核心语言、效应处理和引用监视器。

自然语言接口变得可靠的标志，也是自然语言退回表面，把这一层中间结构让出来。模型适合把欠规定的意图阐述成结构，并在结构的空位上提议候选。类型检查、权限、重放和正确性里写得出性质的那一部分，由运行时承担。这些角色在编程语言里都曾经由谨慎承担，后来被可检查的纪律替换。替换的原因是谨慎无法组合。

## 锚点

正文里点名的工作，只作为进一步阅读的入口。机制的取舍不依赖某一篇论文的实验数字。

- Beurer-Kellner 等，*Prompting Is Programming*（LMQL）：把脚本和输出约束放进对模型的查询。
- Khattab 等，*DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines*（ICLR 2024）：把声明式语言模型调用编译成可优化的流水线。
- 代数效应与处理程序用于语言模型程序和有界提示流水线的工作：同一段请求可以解释为执行、记录、重放或沙箱；轨迹需要带结局。
- Fides（arXiv:2505.23643）：用信息流标签约束代理规划，并用隔离查询取出类型化结果。
- FLOWSEAL（arXiv:2609.14003）：在模型上下文之外，按来源强制机密性。
- APPA（arXiv:2607.24625）：在工具分发和协议网关上做可恢复的信息流控制，并讨论渐进安全类型。
- 多代理控制流劫持（ICLR 2026 一类工作）：委托返回值成为完整性通道；困惑的代理见 Hardy, 1988。
- 语言实现中的外部语言、阐述与内部语言，见 Harper 一系的说法。渐进类型见 Siek 与 Taha。契约失败时的责任分配见 Findler 与 Felleisen，以及 Wadler 与 Findler。
- 信息隐藏见 Parnas；抽象与表示无关见 Reynolds；结构化控制见 Dijkstra；小规模与大规模编程见 DeRemer 与 Kron；下一个 700 种语言见 Landin；言语行为见 Austin 与 Searle。
